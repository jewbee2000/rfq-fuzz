# Workspace-local Linux fallback provenance

The coordinator authorized a separate, workspace-local QEMU TCG guest after the Docker/WSL backend failed. Existing host VMs and host settings were not modified. No system-wide installer was run.

QEMU's [official download page](https://www.qemu.org/download/) links Stefan Weil's [Windows builds](https://qemu.weilnetz.de/w64/). The downloaded binary was [qemu-w64-setup-20260811.exe](https://qemu.weilnetz.de/w64/qemu-w64-setup-20260811.exe), listed as QEMU 11.1.0. Its locally calculated SHA512 matched the [published checksum](https://qemu.weilnetz.de/w64/qemu-w64-setup-20260811.sha512): `5bcf9eed634e8575a37b74f445af41a2fe4106da512d0c30c368301d4c105037fdfab40a5287367a28a957624cddebbc8c07e16c88ab6634f554cdf3d16bf543`. The extracted runtime reports `11.1.0 (v11.1.0-12130-ge470268ff4)`.

The installer was extracted with the existing 7-Zip 24.03 executable; it was never executed. Extracted files remain under `work/consumer-env/qemu`, including COPYING, COPYING.LIB and firmware license notices. QEMU is GPLv2 overall, with separately licensed firmware and components; see its [upstream license](https://gitlab.com/qemu-project/qemu/-/raw/master/LICENSE). The build site's expired-certificate caveat was recorded during source verification; checksum equality is recorded separately from signature verification.

The guest uses Canonical's [Ubuntu 24.04 minimal cloud image, release-20261001](https://cloud-images.ubuntu.com/minimal/releases/noble/release-20261001/ubuntu-24.04-minimal-cloudimg-amd64.img). The local image SHA256 matched the [published SHA256SUMS](https://cloud-images.ubuntu.com/minimal/releases/noble/release-20261001/SHA256SUMS): `a8eb6570f87a941f3de2e000c046b9367f8ab1423756a94830d454fae8ad80ff`. The detached signature was not independently verified. The original image is a read-only qcow2 backing file for a separate 16 GiB overlay; mutable UEFI variables and a NoCloud seed also remain workspace-local. The image is an aggregate with package-specific licenses; its package manifest was retained.

The setup-only ISO helper `pycdlib==1.14.0` is installed in `work/consumer-env/tooling-venv`, separate from both project environments and the unchanged M0 project lock. Its install report/log retains artifact metadata. Guest setup only retrieves explicit setup files/project archives from a localhost-only host server through QEMU's user-mode network. A later source archive transfer used a temporary SSH reverse forward to that same localhost HTTP server; the guest remained externally restricted and the forward closed before replay. The final demo used `restrict=on`, which QEMU documents as isolating guest routing while permitting explicitly configured localhost forwarding. The actual guest route table had no default route, an external connection failed (curl exit 7), and no temporary reverse transfer listener remained. Source packets were not sent to hosted services.

Exact download/checksum/extraction/version logs, launch JSON, overlay creation, guest serial startup and setup commands were retained. First boot did not discover a SATA seed CD; virtio attachment fixed discovery but exposed an emulated IO-APIC timer panic. The model was revised to direct-kernel boot with `noapic`, using the original verified image's extracted vmlinuz 6.8.0-146-generic/microcode and root PARTUUID. That boot completed successfully. Current runtime does not use the initial mutable UEFI variables. Four virtual CPUs with TCG multi-threading subsequently booted stably; this is software emulation, not privileged hardware acceleration.

Actual Ubuntu 24.04.5/kernel 6.8.0-146/glibc 2.39/Python 3.12.3 and Poppler 24.02.0 setup passed pip check, nine imports, actual export smoke, complete 15-case offline replay and own three-family STEP/PDF/PNG inspection. The named slow-emulation profile required explicit 300-second native/120-second document-audit bounds; the initial 60-second timeout remains a failure. The portable runtime lock now explicitly includes two observed conditional Linux IPython pins. System and distribution license notices were exported. Only sanitized logs/provenance/licenses/consumer outputs are handed into evidence; keys, seed contents, disks and provisioning executables are excluded.
