# Frozen provisional M0 contract, version m0.1

This is the first-case spike, not completion of T04. Shared contracts are fixed before a second implementation worker starts.

Each public case folder contains only `packet.json`, `part.step`, `drawing.pdf`, `drawing.png`. Case IDs are opaque. PacketSpec fields: `schema_version`, `case_id`, `part_id`, `release_association` (model/drawing ID and permitted revisions), `units` (model/drawing), `authority` (model nominal geometry, drawing tolerances and manufacturing instructions), `manufacturing` (model_stage, drawing_stage, explicit transition or null, material and finish), `profile` (synthetic M0 scope; no advisory thresholds), `setup` (orientation only), `features` (H1 public hole-group association, XY center membership), `obligations`, `artifacts` (path/hash/media type). Packet SHA-256 is the actual packet.json byte hash. STEP itself must declare millimetres.

Finite consistency obligation `bore_group_consistency`, feature `H1`: four XY centers (-25,-15), (-25,15), (25,-15), (25,15); all parallel Z, through an 80 x 50 x 8 mm single plate. The drawing should visibly show a single group callout `4x diameter D +/-0.05 THRU`. Source numeric labels must be read from final PDF and matched with the visible raster. Do not infer dimensions from pixel scale.

Same stage: drawing interval must include the nominal bore measured from STEP. Later-stage ream: model is intermediate, drawing is the required final bore; an explicitly declared reaming operation applying to H1 explains a larger final diameter. This only establishes finite package consistency, not tooling/workholding or physical feasibility. Declared material 6061-T6, finish none; no inferred coating allowance. Both stage premises must also appear in visible drawing notes. Views explicitly depict the supplied model at its model stage; numeric callouts apply at the drawing stage. All other drawing/model identity and envelope obligations stay invariant. Valid alternative legitimately changes stage contract and notes; defective/repair changes only bore numeric annotation. Nonsemantic automatic layout reflow is allowed if labels remain visible and their association is unambiguous. All three STEP geometries are identical.

Validator ownership: separate module/process; direct OCCT STEP reader rather than generator imports; analytic volume = 80*50*8 - 4*pi*3^2*8. Check BRep validity, one solid, envelope, four full circular cylinder walls radius 3, Z axis, centers/depths, analytic volume, STEP units and actual files/hashes/signatures. Tolerance: geometry lengths/centers 1e-6 mm, volume 1e-5 mm3. PDF extraction must retain positions and actual ink/region evidence; rendering uses an independent engine. Automated raster-region checks and coordinator visual attestation are both required. A whiteout retaining searchable text must fail. Quarantine invalid fixtures with reasons; retain corrupted negative inputs/evidence. Do not use generator-side answers as measurements. Shared OCCT kernel is a disclosed common-mode limit.

Private output at `evidence/M0/private/`: MutationSpec mapping opaque cases to defective/repaired/valid and allowed deltas; OracleRecord independently observed STEP/drawing/stage evidence and validation status. Output evidence directory `evidence/M0/validation/` contains actual parser measurements, rendered regions and validation records. Do not export it to the reviewer.

ReviewResult and Finding schema is `schemas/m0-review-result.schema.json`. Reviewer receives only public cases, neutral instructions and this output schema. Covered conclusion classes: contradiction, profile_exclusion, advisory, missing_information, supported_clear, unsupported. Execution states: completed, partial, unsupported, timeout, error. Invalid fixture is a validator state. Each finding names public feature/obligation, geometric and drawing witnesses and rationale. M0 scoring covers only the named bore obligation; all CNC advisories remain explicitly unsupported. Unmatched findings are unadjudicated. No general manufacturability score.

Commands planned before implementation: `python tools/m0.py generate`, `python tools/m0.py validate`, `python tools/m0.py reference`, `python tools/m0.py report`; `python -m pytest tests/m0`. T02 closure needs actual measurement/visual evidence and negative checks. T03 closure needs genuinely isolated review of drawing, STEP and context, plus inspectable regression report.
